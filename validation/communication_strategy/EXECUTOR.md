# Исполнение коммуникационного модуля

1. Получить от главного агента подтверждённый brief и доступные продуктовые результаты; не проводить повторное вводное интервью.
2. Проверить запрос по contracts.json; прочитать состояние кейса, если оно доступно. При конфликте ревизии не перезаписывать данные.
3. Выполнять только запрошенное действие. Для run_next_stage выполнить ровно один следующий этап C01–C06.
4. Для этапа прочитать method_routing.yaml: базовые методы рассмотреть всегда, условные — только если они могут изменить решение; записать почему метод выбран или пропущен.
5. Выполнить выбранные methods/*.yaml на реальных доступных данных. Разделять user_reported, public_source, user_document, hypothesis, synthetic_example и model_calculation. Отсутствие исследований людей означает awaiting_data/partial, а не вымышленные интервью.
6. Сохранить собственную копию входного брифа, результат метода, результат этапа, ограничения, состояние и историю **только** в `cases/{case_id}/communication_strategy/` по `workflow.yaml`. Общий `cases/{case_id}/brief.json` принадлежит `common_intake` и доступен только для чтения; `product_strategy/` не изменять. Если реальное сохранение недоступно, вернуть артефакты с saved=false.
7. После каждого этапа вернуть управление родителю для согласования. Не продолжать без approve_stage.
8. После C06 собрать единую стратегию, даже если отдельные этапы partial. Явно пометить гипотезы, альтернативы, продуктовые зависимости и план проверки.
9. При обновлении вводных пересмотреть только затронутые результаты и сохранить историю, если хранилище позволяет.
10. Не изменять другие каталоги, не делать неподтверждённых заявлений о запуске кода или интеграции.
