# Подключаемый модуль продуктовой стратегии v0.2 — без обязательного кода

## Что входит в комплект

Это модуль для **встраивания в главного агента**, а не автономная LLM-программа. Внутри: 21 неизменённая методика YAML, согласованный семиэтапный роутинг, декларативный жизненный цикл, JSON Schema контракт обмена, инструкция исполнителя и примеры. **Python не нужен**, чтобы исполнять декларативный маршрут; он остаётся необязательным инструментом для расчётов/формальной проверки схем.

Главный агент самостоятельно проводит краткое интервью, подтверждает вводные, общается с человеком, согласует результаты, интегрирует продуктовую и коммуникационную стратегии. **Только после подтверждения** он вызывает этот модуль через протокол `handoff.yaml`.

## Порядок чтения

1. `MODULE.md` — главное назначение и границы.
2. `handoff.yaml` — кто за что отвечает и какими сообщениями обмениваются компоненты.
3. `workflow.yaml` — семь этапов и жизненный цикл.
4. `method_routing.yaml` — соответствие 21 методов этапам (точная копия согласованной карты маршрута).
5. `contracts.json` — JSON Schema для формы запросов/ответов/артефактов.
6. `EXECUTOR.md` — поведение LLM-исполнителя.
7. `methods/*.yaml` — собственно методики.

`examples/` — только демонстрация интерфейса. Это не реальные исследования.

## Минимальный вызов

Главный агент присылает объект `module_request` с `action:start_case`, `case_id` и подтверждённым брифом. Модуль возвращает `module_response` со ссылками или содержимым `brief.json` и `state.json`. Следующий запрос `run_next_stage` формирует методические результаты и результат S01; затем `approve_stage` разрешает S02. И так до S07. В любой момент можно вызвать `get_status`. Реальные данные практического метода добавляются через `attach_human_data`. После семи этапов `get_outline` возвращает каркас продуктовой стратегии.

Здесь **нет собственных команд CLI, localhost-сервера, вызова OpenAI API или обязательной привязки к IDE**. Встраивание означает, что платформа главного агента должна передавать инструкции, сообщения и результаты между своими компонентами; если она не предоставляет такого механизма, потребуется несложный адаптер на её стороне.

## Что необходимо от принимающей системы

- Доступ к утверждённым YAML (файлы или полный текст в контексте).
- Возможность передать и принять JSON-объекты.
- Возможность обеспечить **постоянное хранение** брифа, состояния, отдельных результатов и версий — непосредственно либо средствами главного агента.
- Разрешённые источники для исследования. Наличие LLM не означает, что ей доступен веб или внутренние файлы.
- Для точной статистики — проверяемый вычислительный инструмент, если она требуется по методике. При его отсутствии анализ остаётся `partial`.

Проверка `contracts.json` — обязательное правило протокола; машинное обеспечение строгой проверки зависит от среды. Без инструмента JSON Schema LLM может лишь сверять поля по спецификации, а не гарантировать математически корректную запись. Это честное ограничение варианта без обязательного кода.

## Файловая раскладка одного кейса

```text
cases/CASE_ID/
├── brief.json
├── state.json
├── inputs/                 # только разрешённые данные для выбранных методов
├── results/
│   ├── methods/M01.json  # файлы только действительно выбранных методов
│   ├── stages/01_stage.json
│   └── product_strategy_outline.json
└── history/                # версии при обновлении, без перезаписи исходников
```

Кейсы и пользовательские данные **не добавляются в GitHub**. Содержимое текущего комплекта можно впоследствии перенести в отдельную папку проверки, не трогая корневые `AGENTS.md`/`methodology.md` коллеги.

## Практические методы

При отсутствии реальных интервью, опросов или экспериментов модуль возвращает `data_requests[]` и `awaiting_data`, а главный агент передаёт человеку инструкцию. Сбор данных модуль не имитирует. Другие этапы продолжаются и могут иметь статус `partial`. Позднее `attach_human_data` продолжает конкретную методику и помечает затронутые результаты на пересмотр без запуска семи этапов с нуля.

## Конфликты и миграция с v0.1

v0.1 — самостоятельный локальный сценарий с `AGENTS.md`, `product_wrapper/` и Python CLI. **v0.2 его заменяет в качестве рекомендуемого интеграционного интерфейса**. Старые файлы остаются на Google Drive как архивный вариант и не являются обязательными зависимостями v0.2. `MODULE.md` — точка входа вместо локального `AGENTS.md`. Назначение и содержание 21 методик, семь этапов и прежние результаты методологического аудита **не меняются**.

Примеры сценариев и смысл полей — в `INTEGRATION.md` и `examples/`. Версия интерфейса `0.2` относится только к обвязке, не к самими методикам.
