# Минимальная инструкция интегратору главного агента

Наш продуктовый модуль не следует запускать при открытии чата. Он подключается после того, как главный агент завершил **своё** интервью и подтвердил существенные вводные с пользователем.

**Главному агенту достаточно:**

1. Сформировать подтверждённый бриф по `contracts.json#/$defs/brief` и передать `start_case`.
2. После приёма состояния последовательно вызывать `run_next_stage`, каждый раз получать результат одного этапа, показывать его человеку и передавать `approve_stage` после согласования. Семь этапов фиксированы.
3. Когда модуль возвращает `data_requests`, предоставить человеку описание нужного интервью/опроса/пилота и вернуться к методу через `attach_human_data` после получения **настоящих** данных. Остальные этапы можно продолжать в `partial`.
4. Через `get_outline` получить черновой каркас продуктовой стратегии. Соединить его с коммуникационной частью общего агента на своей стороне.

**Обязательные файлы исполнения:** `MODULE.md`, `workflow.yaml`, `method_routing.yaml`, `handoff.yaml`, `contracts.json`, `EXECUTOR.md` и выбранные YAML из `methods/`. Не надо запускать `engine.py`, `cli.py`, `AGENTS.md` из старого локального комплекта.

**Формат связи:** вход `module_request`, выход `module_response` (примеры `examples/start_case.request.json`, `examples/run_next_stage.response.json`). Возвращённые артефакты с `saved:false` должен сохранять **главный агент**, иначе обещать долгосрочное продолжение нельзя.

**Граница ответственности:** продуктовая сегментация, рынок, конкуренты, цена, экономика, каналы, риски, альтернативы и каркас продуктовой стратегии — наш модуль; диалог, общее управление и коммуникационная стратегия — главный агент.

В GitHub модуль можно положить в отдельную папку проверки, **не изменяя** корневые `AGENTS.md` и `methodology.md`.
