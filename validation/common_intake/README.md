# Модуль первичного интервью и общего брифа v0.1

## Назначение

Подключаемый компонент главного агента для первичного разговора с инициатором продукта. Один источник вводных для последующего продуктового и коммуникационного анализа. **Не самостоятельный консультант и не часть метода интервью M11.**

Базируется на текущих `AGENTS.md` и `methodology.md` репозитория `Allishich/Agent_Allish` и на существующем JSON-контракте продуктового модуля v0.2. Источники использованы без изменения исходных файлов.

## Архитектура

```
инициатор → адаптивный диалог главного агента → discovery.md (история)
                                          └──→ brief.json (общий подтверждённый источник)
                                                     ├──→ product start_case (действующий контракт v0.2)
                                                     └──→ communication module_request v0.1
                                                          confirmed_brief = полный brief.json
                                                          product_strategy_outline = отдельно
```

## Состав

- `INTERVIEW_MODULE.md` — инструкции по диалогу и подтверждению.
- `intake_workflow.yaml` — состояния и последовательность.
- `brief.schema.json` — строгая структура общего брифа (JSON Schema 2020-12).
- `brief_mapping.yaml` — способы выдачи проекций обоим модулям.
- `communication_context.schema.json` — **устаревший проектный** формат коммуникационного контекста; активный вход описан в `validation/communication_strategy/contracts.json` и `brief_mapping.yaml`.
- `INTEGRATION_PLAN.md` — адресные изменения для последующего общего PR; пока ничего в GitHub не меняем.
- `examples/` — синтетические, обезличенные образцы рабочего журнала, брифа и модульных запросов.
- `VALIDATION.md` — технические проверки с ограничениями.

## Важное разграничение

`discovery.md` хранит последовательность уточнений и рабочие заметки. `brief.json` — один актуальный источник данных, который модули читают на момент старта/обновления. Подтверждение брифа означает «верно записано со слов инициатора», **не** «рынок доказан». Значения `null` и `[]` допустимы.

Продуктовый адаптер валидируется по существующему `validation/product_strategy/contracts.json`, поэтому контракт продуктового модуля переписывать не требуется. Для коммуникационной части декларативно согласован `module_request` протокола `0.1`: целый подтверждённый `brief.json` передаётся в `confirmed_brief`, проверяемый продуктовый каркас — отдельно в `product_strategy_outline` (или `null`). Полнота исходного брифа проверяется по `brief.schema.json`, оболочка — по контракту модуля. Сквозное исполнение, сохранение и runtime-адаптер этим не подтверждены.

## Среда исполнения

Python, Codex, Cursor, сеть, Drive API и файловая система **не обязательны для понимания инструкций**. Для фактической записи/возобновления агенту или его хосту всё же необходимо долговременное хранилище. В отсутствие инструментов записи вернуть полный текст брифа с отметкой `unsaved`, а не заявлять о сохранении.

Данные реальных пользователей не включаются в репозиторий; в будущем PR — только спецификации и синтетические примеры. Согласованная версия в Google Drive остаётся исходной до единого итогового PR.
